# Nasir-DB — نسخه دوم

این شاخه (`version-2-json`) نسخه‌ی دوم برنامه است. نسخه‌ی فعلی محلی شما در شاخه‌ی `main` دست‌نخورده می‌ماند.

## ذخیره‌سازی

- روی Vercel، همه‌ی جدول‌های برنامه—از جمله کاربران، رمزهای هش‌شده، نشست‌ها، تنظیمات، مشتریان، بل‌ها، پرداخت‌ها و گزارش‌ها—در یک فایل JSON خصوصی در Vercel Blob نگهداری می‌شوند.
- برای توسعه‌ی محلی، فایل در `.data/companymanager-v2.json` ساخته می‌شود و وارد Git نمی‌شود.
- نوشتن روی Blob با ETag محافظت می‌شود؛ اگر هم‌زمان درخواست دیگری داده‌ها را تغییر دهد، تغییر جدید با خطای تعارض رد می‌شود تا اطلاعات قبلی بی‌صدا بازنویسی نشود.
- داده‌ی شاخه‌ی فعلی یا فایل SQLite آن خودکار به نسخه دوم منتقل نمی‌شود. نسخه‌ی دوم پس از راه‌اندازی، پایگاه‌داده‌ی JSON جداگانه‌ی خود را آغاز می‌کند.

## راه‌اندازی نسخه دوم در Vercel

1. در پروژه‌ی Vercel به **Storage → Create Storage → Blob** بروید و یک Blob Store با دسترسی **Private** بسازید.
2. آن را به همین پروژه و محیط **Production** (و در صورت نیاز **Preview**) وصل کنید تا Vercel متغیرهای دسترسی لازم را تنظیم کند.
3. شاخه‌ی `version-2-json` را به‌عنوان شاخه‌ی Production پروژه انتخاب کنید، یا ابتدا Preview آن را بررسی کنید.
4. پس از استقرار موفق، صفحه را باز کنید و حساب مالک را در راه‌اندازی اولیه بسازید.

فایل داده در مسیر `companymanager/database-v2.json` داخل Blob Store قرار می‌گیرد. توکن Blob را در کد یا Git قرار ندهید.

## فایل اجرایی ویندوز

این فایل کوچک با یک کلیک سایت Production را در مرورگر پیش‌فرض ویندوز باز می‌کند؛ داده‌ها همان داده‌های آنلاین Vercel Blob هستند. فایل برای اجرا به اینترنت نیاز دارد.

فایل آماده: `release/NasirDB.exe`

برای ساخت دوباره در Windows از دستور `npm run desktop:dist` استفاده کنید. مقصد فایل اجرایی `https://nasir-db.vercel.app` است.
